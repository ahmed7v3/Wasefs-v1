# Prescription report v2 — PDF, calendar file and the WhatsApp result (spec, 2026-10-31)

> **Owner request (2026-10-31):** after an analysis on WhatsApp, send a well-formatted PDF report with the full
> details (dosing schedule, instructions, full breakdown) at the depth of the website, not only text.
>
> Builds on PR #72 (`feat/wa-rx-detail`: per-medicine cards, `packages/shared/src/rx-schedule.ts` suggested
> times, timetable in `rx_result.typ`) and the Typst renderer (`apps/worker/src/documents/*`, `WA-AGENT.md`
> §8a: fixed templates, data as JSON shown as text, never evaluated; fresh temp dir; 20 s, 5 MB, 30 pages).
> Data: result schema v2 (`RX-ENGINE.md` §6). Rules: AGENT §5.10 (i18n, RTL), §5.11 (disclaimers, uncertain
> items highlighted, never fabricated names).

---

## 1. The PDF report (`templates/rx_report.typ`, replaces `rx_result.typ`; A4, RTL, IBM Plex Sans Arabic)

Every value comes from the stored result (`rx_analyses.result`) and the database, never from model prose
written for the report. Sections, in order:

1. **Header band:** brand mark, «تقرير قراءة الروشتة», analysis date (Cairo), prescription date when read, a
   short reference (`RX-7F3K`) and a **QR code** to `/analyze/<id>` (signed-in page; the QR is generated by
   Typst's own drawing from data — no network).
2. **Summary card:** number of medicines; status line from tiers («٤ أدوية واضحة · ١ محتاج مراجعة»); the
   findings callout (duplicate ingredient, strength not available, dose unit vs form, unusual frequency) in
   caution colour; the quality note when the photo was `fair`.
3. **Today's plan — dosing timetable:** a day grid with four bands (الصبح · الضهر · المغرب/العصر · قبل
   النوم) and clock times from `rx-schedule.ts` (or the customer's own routine when Companion knows it), one
   row per medicine with dose and meal relation icons (before/after/with food); «مواعيد مقترحة — اتبع تعليمات
   طبيبك» always printed. Lines with no frequency say «حسب تعليمات الطبيب» (no invented slots).
4. **Medicine cards** (one per line, never split across pages):
   - title: database name (asserted tiers) or the reading (`ai`) or «X أو Y» (`uncertain`); tier badge
     (none / «مرجّح» / «راجِع» / «قراءة آلية» / «غير مقروء»);
   - **the line as written:** the crop of that line from the prescription (from the master image, max 900 px
     wide, grayscale, JPEG) — the reader can compare the reading with the handwriting (strongest trust signal);
   - facts grid: المادة الفعالة · التركيز · الشكل · الجرعة · عدد المرات · المدة · طريقة الاستخدام · تعليمات
     الطبيب (notes) — empty facts are omitted;
   - general information (details step): بيستخدم لـ · أشهر الأعراض الجانبية (≤ 5) · احتياطات (≤ 4), titled
     «معلومات عامة عن الدواء — مش بديل عن رأي الطبيب»;
   - for `uncertain`: the top 2–3 candidates with strength/form and «اتأكد من الصيدلي».
5. **Course calendar** (when durations are known): a 7- or 14-day checklist (day columns × dose rows) with
   empty tick boxes, so the report doubles as an adherence sheet for the fridge.
6. **For the pharmacist:** compact table (name · ingredient · strength · form · quantity per day · days) — the
   page a family member shows at the counter.
7. **Notes and limits:** unreadable areas («جزء من الروشتة مش مقروء»), the medical disclaimer (i18n
   `rx.disclaimer`), «التقرير ده بيساعدك تفهم الروشتة، والقرار لطبيبك والصيدلي».
8. Footer on every page: page x/y, reference, «wasfa.online».

Format rules: numbers in Western digits (AGENT §5.10 default) with Arabic labels; Latin drug names isolated for
bidi; no colour-only meaning (badges carry text); printable in grayscale; ≤ 6 pages for 10 medicines; file name
`wasfa-rx-<yyyy-mm-dd>.pdf`.

## 2. The WhatsApp result message (deterministic, `apps/api/src/wa-agent/rx/rx-messages.ts`)
Sent in this order, under the conversation lock:
1. **Summary text** (one message, ≤ 1200 chars):
   ```
   ✅ *قريت الروشتة* — ٤ أدوية
   1) *Bepra 20* قرص — قبل العشاء
   2) *Riopan* شراب — معلقة بعد الأكل · 3 مرات
   3) *Glibimet 5* (مرجّح) — نص ساعة قبل الأكل
   4) ⚠️ مش واضح: *Motilium* أو *Motinorm* — راجع الصيدلي
   ⚠️ دوائين فيهم نفس المادة الفعالة: … 
   📄 التقرير الكامل والمواعيد في الملف
   ```
2. **The PDF** (document message, caption «تقرير الروشتة + جدول المواعيد»).
3. **Calendar file** (optional, setting on by default): `wasfa-doses.ics` (§3) with caption «لو عايز المنبه
   في موبايلك افتح الملف ده».
4. **Voice summary** (optional: voice enabled and the customer uses voice, or asked): ≤ 45 s, the plan in
   Egyptian Arabic, generated from the same deterministic text (no model prose), ElevenLabs as today.
5. **Next steps line:** «اسألني عن أي دوا · اكتب *مواعيدي* · اكتب *فعّل التذكير*».
A render failure sends 1 and 5 plus «الملف هيوصلك بعد شوية» and retries the render twice (outbox); the web
result stays the source of truth.

## 3. Calendar file (`packages/shared/src/rx-ics.ts`, pure)
- RFC 5545 `VCALENDAR` with one `VEVENT` per dose slot and an `RRULE` (`FREQ=DAILY;COUNT=<days>` when the
  duration is known, else 7 days with a note), `VALARM` at the time (`TRIGGER:PT0M`), `TZID=Africa/Cairo`
  (or the customer's zone), summary «💊 Bepra 20 — قرص قبل العشاء», UID `<rxRef>-<line>-<slot>@wasfa.online`
  (re-import updates instead of duplicating).
- Only asserted lines with a parsed frequency; `uncertain`/`ai` lines are excluded (never an alarm for a
  medicine we are not sure of). Description carries the «مواعيد مقترحة» notice.
- This gives phone-native reminders with **zero WhatsApp ban risk** (no outbound messages at all).

## 4. Website parity
The same report is downloadable on the web result page («تحميل التقرير PDF»), rendered by the same worker job
(`documents` queue, `rx.report` job), cached per result version (`rx_reports` row: `result_version`, `key`),
regenerated when the user corrects a line. The web print sheet (`rx-print-sheet.tsx`) stays for browser print.

## 5. Data contract (`rxReportDocSchema`, zod, worker side)
Built by `apps/worker/src/documents/rx-report-data.ts` from the result v2 + DB lookups: header, summary,
schedule grid, cards (with crop object keys resolved to bytes inside the render dir only), calendar, pharmacist
table, labels (i18n). The template never computes medical content; it lays out what the data says.

## 6. Tests
Golden PDFs for fixtures (printed 3 lines, hard handwriting 6 lines with 2 `uncertain`, 12-line multi-page,
no-frequency lines, duplicate ingredient): text extraction asserts sections, order, Arabic shaping (no isolated
forms), bidi of mixed lines; page count budget; render time < 5 s; ICS validated by a parser round-trip and
`icalendar` lint rules; WhatsApp summary snapshot per tier mix; fallback when render fails.
